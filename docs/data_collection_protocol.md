# 데이터 수집 프로토콜 & 클래스 매트릭스 (멀티모달 · 로터+베어링)

스마트폰 **영상(저주파 변위)+음향(고주파 결함)** 멀티모달 진단 논문을 위한 데이터 수집 설계.
각 모달리티를 **물리적 강점에 맞춰** 배치하고(영상→로터, 음향→베어링), **복합결함으로 융합을 정당화**하며,
**처음부터 누수 없는 분할**이 가능하도록 수집한다.

> 결정 배경·역할분담은 [paper_concept.md](paper_concept.md) 1-B, 물리적 근거는
> [fps_temporal_resolution_analysis.md](fps_temporal_resolution_analysis.md),
> [audio_feasibility_analysis.md](audio_feasibility_analysis.md), [multimodal_related_works.md](multimodal_related_works.md) 참고.

## 1. 결함 분류 체계 (멀티라벨 2-헤드)

곱집합으로 클래스를 폭발시키지 않고 **두 축의 멀티라벨**로 구성한다.

- **로터축 (영상이 강점):** {없음, **U**(불평형), **M**(정렬불량), **L**(풀림)}
- **베어링축 (음향이 강점):** {**H**(정상), **IR**(내륜), **OR**(외륜), **B**(볼)}

한 샘플의 라벨 = (로터축 상태, 베어링축 상태). 예: `(U, OR)` = 불평형 + 외륜결함(복합).
복합결함(로터≠없음 AND 베어링≠H)은 off-diagonal을 채운다. (U+M 등 로터끼리 복합은 선택.)

### 클래스 매트릭스 (4×4)
| 로터＼베어링 | H | IR | OR | B |
|---|---|---|---|---|
| **없음** | 정상(baseline) | 베어링단독 | 베어링단독 | 베어링단독 |
| **U** | 로터단독 | 복합 | 복합 | 복합 |
| **M** | 로터단독 | 복합 | 복합 | 복합 |
| **L** | 로터단독 | 복합 | 복합 | 복합 |

- **Phase 1 (코어):** 대각·1축 = 정상1 + 로터단독3 + 베어링단독3 = **7 조건**. → 역할분담·ablation 입증만으로 논문 성립.
- **Phase 2 (헤드라인):** 복합 3×3=9 중 **대표 3~4조합**(예 U+OR, M+IR, L+B, U+IR) → 융합의 결정적 우위 실증.
- **Phase 3 (선택):** 촬영조건 강건성, 960fps 비교, 로터복합.

## 2. 물리적 변이 전략 (누수 없는 데이터를 만드는 법)

### 2-1. RPM (정상상태 다중 설정점 — 실시간 가변 아님)
- **최소 3 설정점**, 권장 4: **900 / 1200 / 1500 / 1800 rpm**.
- 각 기록은 **상수 RPM 정상상태** → 시변 order-tracking 불필요(분석 단순화).
- 속도 간 특징 정렬은 **order 정규화**(주파수 ÷ 측정 회전주파수 fr)로 수행.

### 2-2. 반복 기록 (세그멘테이션 누수 차단)
- 조건·RPM당 **독립 기록(take) ≥3회** — **반드시 별도 start/stop**으로 촬영.
- ⚠ 한 긴 영상을 슬라이딩 윈도우로 쪼개 train/test에 나누면 **세그멘테이션 누수**(포스터의 약점). 독립 take로 분할해야 함.

### 2-3. 재장착 정책 (개체(instance) 누수 차단) — 계층적/조건부
- **베어링 3종(IR/OR/B): 데모 서브셋에 대해 재장착 2~3회 필수.** → 개체 held-out 테스트 성립(포스터가 못 한 검증 = 논문 신뢰도 핵심).
- **그 외(로터 U/M/L·복합): 필요 시(as-needed).** 로터는 조절 조건이라 개체누수 위험 낮음.
- 각 재장착 = 독립 instance id 부여. 같은 결함이라도 재장착 시 seating/두께 편차가 개체 다양성 제공.

> **왜 필수인가:** RPM만 바꾸고 물리 베어링 1개면, 모델이 "결함 종류"가 아니라 "이 개체 지문"을 외워도 정확도가 높게 나온다(포스터 99.7% 의심 지점). RPM 교차분할은 **속도 불변성**만, 재장착은 **개체 불변성**까지 검증.

## 3. 누수 없는 분할 전략

| 분할 | 방법 | 검증하는 것 |
|---|---|---|
| **개체 held-out** (주) | 베어링 재장착 instance로 train/test 분리(예 inst1·2 학습 → inst3 테스트) | **개체 불변** 결함 학습(포스터 미검증) |
| **RPM 교차** (부) | 일부 RPM 학습 → held-out RPM 테스트(예 900·1500 → 1200) | **속도 불변성** |
| **take 분리** (기본) | 같은 조건이라도 독립 take를 train/test에 안 섞음 | 세그멘테이션 누수 차단 |

- **평가지표:** multi-label 이진공식화 + **Macro AUROC**(유병률 독립) + per-class. 튜닝 시 **Double/Nested-CV**.
- 프로토콜 근거: [related_works.md](related_works.md) E2(MSSP 2026), [data_leakage_analysis.md](data_leakage_analysis.md).

## 4. RPM–Nyquist 경계 (영상이 베어링을 어디까지 보나) — 6204 기준

6204: n=8, d=7.94mm, D=33.5mm, θ=0 → 오더 BPFO=3.05·BPFI=4.95·BSF=1.99·FTF=0.38 ×fr.
영상 240fps → **Nyquist 120Hz**.

| RPM | fr(Hz) | BPFO(Hz) | BPFI(Hz) | 영상 120Hz 커버 |
|---|---:|---:|---:|---|
| 900 | 15 | 46 | 74 | BPFO·BPFI ✅ |
| 1200 | 20 | 61 | 99 | BPFO·BPFI ✅ |
| 1500 | 25 | 76 | **124** | BPFI ❌ |
| 1800 | 30 | 92 | 148 | BPFI ❌ |
| 2100 | 35 | 107 | 173 | BPFI ❌ |

- **BPFI는 ~1455rpm, BPFO는 ~2360rpm 초과 시 영상 밴드 이탈**(고조파는 훨씬 낮은 RPM부터 이탈).
- → **"RPM 올릴수록 영상은 베어링을 잃고, 음향은 그대로"**를 다중 RPM으로 실측 시연 = 멀티모달 필요성의 결정적 그림 + **작동범위(operating envelope)** 정의.
- 로터축(U/M/L)은 1×/2×/3×(≤60Hz대)라 전 RPM에서 영상 밴드 내 → 영상의 안정적 강점 대역.

## 5. 촬영·기록 표준 (메타데이터 로깅)

모든 take에 대해 아래를 기록(앱 메타데이터 기능과 연동, [paper_concept.md](paper_concept.md) 3절):

- 기기/모드: 스마트폰 모델, **240fps**, 해상도, export fps(슬로모션 stretch 보정용).
- 기하: 카메라–대상 **거리·각도**, 삼각대 여부, 마커 색/ROI.
- 환경: **조도(lux)**, 배경소음 수준(가능시).
- 운전: RPM 설정점, **측정 회전주파수 fr**(태코 or 영상), 부하.
- 라벨: (로터축, 베어링축), **instance id**(재장착), take id, 복합 여부.
- 음향: 샘플레이트, 채널, 마이크–대상 거리(Lu 2016: 거리로 음향 급감 → 근접 권장).

> 표준화 이유: 거리·조도는 문헌상 최대 환경요인(음향=거리 취약, 영상=조도 취약). 통제·기록해야 강건성 실험이 성립.

## 6. Ablation 실험 매트릭스 (모든 가설을 한 번에)

입력 = {영상단독, 음향단독, 융합(early/feature/late)} × 타깃 = {로터축, 베어링축, 복합}.

| 실험 | 기대 | 검증 |
|---|---|---|
| 영상단독 → 로터축 | **강함** | 영상의 물리적 강점 |
| 영상단독 → 베어링축 | 약함(경계RPM↑) | ⭐ "블랙박스가 저주파로 베어링 학습?" 가설(H1) 직접 검증 |
| 음향단독 → 베어링축 | 강함 | 음향의 강점 |
| 음향단독 → 로터축 | 중간 | 상보성 근거 |
| **융합 → 복합결함** | **최고** | 헤드라인(단일 모달로 불가) |

- **가설 H1:** 저주파 변위 대역에 베어링 유형 판별정보가 실재하는가 → 누수제거 후 영상단독 성능으로 판정.
  - 생존 → "스마트폰 저주파 변위+DL로 베어링 판별 가능"(독자 발견). 붕괴 → 음향이 판별력 공급 입증. **어느 쪽이든 정직·publishable.**
- 융합 아키텍처 후보: Wang2020[5] 1D-CNN(baseline) → You2024[8] physics-informed(경량 0.62M) / Lin2024[6] cross-fusion transformer. ([multimodal_related_works.md](multimodal_related_works.md))

## 7. 실행 순서

1. **Phase 1 수집:** 7 단일조건 × 4 RPM × ≥3 take (+베어링 재장착 2~3). → ablation 매트릭스 1차.
2. **음향 분별성 확인:** 정상/IR/OR/B 오디오로 BPFO/BPFI/BSF 분별(스크립트 `scripts/analyze_audio.py`, `scripts/plot_audio_figures.py`).
3. **누수 없는 baseline:** 개체 held-out + RPM 교차로 영상·음향 단독 성능(정직한 수치).
4. **Phase 2 복합:** 대표 복합조합 → 융합 우위·H1 판정.
5. **Phase 3(선택):** 촬영조건 강건성, 960fps, 로터복합.
