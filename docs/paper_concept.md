# 논문 컨셉 & 앱 확장 방향 (건설적 종합)

본 문서는 지금까지의 문헌 조사·정독(8편)을 **"우리 앱을 어떻게 확장해 논문으로 만들 것인가"**
관점에서 종합한다. 데이터 누수 분석([data_leakage_analysis.md](data_leakage_analysis.md))은
비판이 아니라 **논문의 신뢰성 기여**로 흡수하고, 중심은 건설적 축(스마트폰 실용성·강건성)에 둔다.

> 목표: (1) 결함진단 **애플리케이션 확장** + (2) **저널 논문화**. 이 둘은 한 몸 —
> 앱이 실험 도구이자 논문의 데모이고, 논문이 앱의 학술적 정당성을 준다.

---

## 1. 한 문장 컨셉

> **"별도 장비 없이 스마트폰만으로 현장에서 End-to-End 회전기계 베어링 결함을 진단하는
> 접근성 높은 시스템을 제안하고, 다양한 촬영·운전 조건에서의 강건성과 누수 없는 정직한 성능을
> 처음으로 함께 보고한다."**

두 축:
- **건설적 축 (주):** 접근성(스마트폰) + 온디바이스 End-to-End(앱) + 강건성(다조건).
- **신뢰성 축 (보조, 기여로 전환):** 누수 없는 평가 프로토콜을 이 분야에 도입.

## 1-A. 포스터(1009.pdf) 대비 델타 ⭐ (저널화의 핵심)

> 노블티는 추상적 "새로움"이 아니라 **우리 포스터가 이미 한 것 대비 무엇을 강화하느냐**의 문제.
> 기준선 = 「스마트폰 카메라를 활용한 비접촉식 지능형 회전기계 결함 진단 시스템」(정보공학회 포스터, `papers/스마트폰_..._1009.pdf`).

### 포스터가 이미 주장한 것 (= 델타가 될 수 없음)
| 이미 있음 | 위치 |
|-----------|------|
| 스마트폰 240fps → HSV 마커 → DisplacementZ → WDCNN 시스템 | 그림1, 2절 |
| **WDCNN 99.7%** + ANN(RMS/Skew/Kurtosis) 비교 | 표1 |
| **Android 앱 내장 · End-to-End** | 그림5, 표2 |
| **FFT로 가속도계와 주파수 일치 검증**(20Hz, 회전주파수) | 그림4 |
| 마커리스 · 조명/노이즈 강건성을 **"향후연구"로 이미 명시** | 3절 마지막 |

→ "앱 만들었다 / 99.7% / FFT 맞다 / ANN보다 낫다"는 **다 쓴 카드**. 반복하면 포스터++.
→ 마커리스·강건성은 포스터가 **스스로 숙제로 적어둠** → 그것만 하면 "약속 이행"이지 약한 기여.

### 저널에서 강화할 것 (델타, 우선순위)
| # | 델타 | 포스터 상태 | 강화 내용 |
|---|------|-------------|-----------|
| ① | **99.7%의 타당성** ⭐⭐ | 무검증(중첩윈도우+베어링1개+random 10-fold) | 누수 없는 **bearing-wise 재평가**로 진짜 성능 규명. 포스터가 예상조차 안 한 축 = 가장 차별적 |
| ② | **그림4 확장: 회전→결함 주파수** ⭐⭐ | 20Hz(회전)만 일치 확인 | 영상 DisplacementZ에 **BPFO/BPFI(결함주파수)가 잡히는가**를 RPM별로 분석 + **240fps Nyquist(120Hz) 경계** 제시. fps한계+판별근거+①타당성을 한 그림으로 연결 |
| ③ | **단일→다조건 강건성 + 불확도** ⭐ | 1200RPM·연속광·삼각대 단일 | RPM·조명·거리·각도·기기 통제실험 + 측정 불확도(GUM). 포스터 약속 이행 + 과학적 심화 |
| (보조) | 모델 심화 | ANN vs WDCNN만 | 최신 벤치마크 + CWRU 전이학습(소규모데이터) + XAI |

### 프레이밍 전환
- **포스터 = "시스템을 만들었다"(PoC).**
- **저널 = "그 시스템이 어디까지·얼마나 정직하게 되는가를 규명했다"(엄밀 검증 + 작동범위 characterization).**
- 델타의 본질 = **새 장치가 아니라 엄밀성(rigor) · 범위(scope) · 정직성(honesty)**. 마커 유지/제거는 논쟁거리 아님.

### 가장 날카로운 한 방
> **"포스터의 그림4를 완성한다"** — 회전주파수 일치(포스터)를 넘어 **결함주파수가 240fps로 잡히는지 / 어느 RPM까지 유효한지**를 규명하고, 그 위에서 **누수 없는 정직한 성능**을 보고. 이 하나가 델타 ①+②를 묶고, 포스터가 만든 근거(그림4)를 직접 이어받으며, 아무도 안 한 영역.

관련: [data_leakage_analysis.md](data_leakage_analysis.md)(①), [fps_temporal_resolution_analysis.md](fps_temporal_resolution_analysis.md)(②), [experiment_design.md](experiment_design.md).

## 2. 문헌으로 확인된 우리 위치 (Novelty)

| 축 | 선행 연구 | 우리 |
|----|-----------|------|
| 카메라 진단(B블록) | 산업 고속카메라·이벤트카메라(고가·특수) | **소비자 스마트폰 240fps** |
| 스마트폰 진동(F블록) | 속도추정·모달분석·구조물 SHM | **베어링 4클래스 결함 분류** |
| 배포 | 대부분 오프라인 후처리 | **온디바이스 앱(Android/iOS) End-to-End** |

- **핵심 gap(문헌으로 재확인):** "스마트폰 + 베어링 결함 분류 + 온디바이스 DL" 교집합은 비어 있음.
  - SURVISHNO(MSSP 2021): 스마트폰으로 회전/진동 분석 → 하지만 IAS·모달, **결함 분류 아님**.
  - 이벤트카메라(IEEE TII 2024): 베어링 결함 분류 → 하지만 **특수 고가 카메라**.
  - Peng(MSSP 2023): 영상→CNN 베어링 진단 → 하지만 **산업 고속카메라(1000fps), markerless**.
- **접근성 서사는 이미 top 저널(MSSP)에서 인정된 가치** (SURVISHNO가 근거) → 우리 주장에 정당성.
- **우리 방향을 top 저널이 명시적 future work로 지목**: Yu & Lubineau(Measurement 2021)는 결론에서
  *"스마트폰 960fps 고속촬영 + 앱 기반 실시간 추적을 향후 탐색할 가치가 있다"*고 적음 → 우리가 바로 그것.
- **경제성 근거**: 저비용 진단 시스템이 상용 대비 $500 vs $8000~45000(Vanraj, R.Soc.Open Sci. 2018 Table6).
  우리는 추가 하드웨어 $0(스마트폰만) → 접근성 논거가 더 강함.

## 3. 앱을 실험 플랫폼으로 (확장 방향)

현재 앱(Flutter, OpenCV 마커추적 + PyTorch/LibTorch 온디바이스 추론)은 이미 논문 실험의
**데이터 수집·처리·추론 도구**로 쓸 수 있다. 논문화를 위해 앱에 추가하면 좋은 것:

| 확장 | 목적(논문 기여) | 난이도 |
|------|-----------------|--------|
| **다조건 촬영 메타데이터 기록** (RPM/거리/각도/조명/기기) | 강건성 실험 데이터셋 자동 태깅 | 낮음 |
| **CSV/logits 내보내기 강화** (이미 일부 있음) | 오프라인 재평가·분할 실험 재현 | 낮음 |
| **마커리스 모드(옵션 A)** — optical flow/phase 기반 변위 | 마커 의존성 제거, 현장성↑ | 높음(연구) |
| **자이로 기반 off-axis 보정** — 내장 자이로로 촬영각도 보정 | 비수직 촬영 강건성(Yu&Lubineau 2021 기법) | 중간 |
| **Android/iOS 결과 일관성 로깅** | 플랫폼 재현성(IR→OR 사례 규명) | 중간 |
| **신뢰도 표시** (softmax + 검출품질 결합) | 현장 신뢰성, 오검출 방어 | 낮음 |

> 앱은 이미 "현장 End-to-End"라는 실용성 데모를 제공 → 논문의 강력한 셀링 포인트.

## 4. 논문 기여 후보 (우선순위)

정독으로 실현 가능성이 검증된 순서:

1. **[주] 접근성 있는 온디바이스 스마트폰 베어링 진단 시스템 제시**
   - 앱 자체가 기여. SURVISHNO가 연 "스마트폰 진동분석"을 **결함 분류+온디바이스**로 확장.
2. **[주] 다조건 강건성 평가**
   - C2(수리구조물) 프로토콜 차용: 촬영각도×스케일×조명 통제 → 상관/정확도.
   - RPM 다양화(참고: Peng 200~3000, 이벤트카메라 1200/1800/2400) — 우리 단일 1200 극복.
3. **[보조→기여] 누수 없는 정직한 평가**
   - E1/E2 방법(recording/bearing-wise 분할, Macro AUROC) 도입.
   - "이 분야 최상위 논문들도 안 한 평가를 처음 적용" = 방법론 기여.
4. **[선택] 마커리스 확장** — phase-based motion(Wadhwa 2013 원조)/optical flow 기반. 장기 연구과제.
   - 물리적 정당성 선례 있음: Wadhwa Fig9(영상 위상→변위→가속도가 접촉식 가속도계와 일치).
   - **스마트폰 마커리스 실현 가능성 확인**: Orak & Ozturk 2018이 **Samsung Note 8·240fps(우리와 동급)로 마커 없이** 캔틸레버 고유진동수 측정 성공. 즉 마커리스가 폰에서 기술적으로 가능.
   - 조명 강건성 기법 확보: 조명-반사 분해(Xiong MSSP 2025, MAC 0.75→0.95).
   - **결정적 제약**: 스마트폰 마커리스 성공 사례는 **전부 저주파 구조 모달(수 Hz)**. 베어링 결함(고주파+4클래스 판별)은 미검증 → fps/저주파 문제는 마커리스로 가도 그대로 남음.
   - **빈 자리 확인**: "스마트폰 마커리스 카메라 + 베어링 결함 분류"는 문헌상 없음(스마트폰 베어링 진단은 전부 내장 가속도계). → novelty 유지.
   - 단 온디바이스 계산부하(steerable pyramid) 고려 필요.
5. **[선택] 모델 해석(XAI)** — Grad-CAM으로 결함 주파수 기여도 시각화.

## 5. 정직한 성능을 "기여"로 프레이밍하는 법

99.7%를 방어하는 게 아니라, **정직한 재평가 자체를 논문의 강점으로**:

- 스토리: *"기존 카메라 기반 진단(및 예비 실험)의 ~99% 정확도는 평가 방식의 낙관 가능성이 있다.
  우리는 스마트폰 파이프라인에서 이를 점검하고, 다조건·누수없는 평가로 **현실적이고 신뢰할 수 있는
  성능**을 보고한다."*
- 이벤트카메라 논문조차 영상<가속도계(95~98% vs 99%)로 정직하게 보고 → 우리도 그런 정직함을 취하면
  오히려 **신뢰도 높은 논문**이 된다.
- 재평가로 정확도가 떨어져도 문제없음 — "접근성+강건성+정직성"이 핵심 가치이지 "최고 정확도"가 아님.

## 6. 실행 로드맵 (앱→논문)

| 단계 | 할 일 | 산출물 |
|------|-------|--------|
| S1 | 현재 데이터 분할 방식 확인 + 분할 비교 재평가 | 누수 곡선(정직한 성능 범위) |
| S2 | 다조건 추가 촬영(RPM·조명·거리·각도·기기) | 강건성 데이터셋 |
| S3 | 앱에 메타데이터/로깅/신뢰도 기능 추가 | 실험 도구화된 앱 |
| S4 | (선택) 마커리스/XAI 실험 | 추가 기여 |
| S5 | 결과 종합 → 논문 초안 | 저널 원고 |
